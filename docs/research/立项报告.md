## 0. 一句话

**DeepSeek Super-agent 证明了"会干活的 agent 舰队"可行,但没有解决"敢让它干活"。本项目造的是中间这一层:给双层调度装上组织、边界、契约与治理——并且整套东西在没任务时零进程零 token。**

三个事实支撑这个定位:

1. **官方自认的安全债**:superagent 的 Worker/Router 全部以操作者 OS 用户 `danger-full-access` 裸奔,官方文档原话承认凭据包装"建立默认,不是安全边界",部署隔离是未解决的开放问题(docs/006-deployment.md、docs/007-architecture.md)。
2. **官方自认的信任空洞**:prompt 层的合并纪律、诚实条款"约束 agent 而非系统规则"(docs/004-prompts.md、003-execution.md);业界调研同样证实:没有任何系统把谎报当组织问题治理——没有证据链、没有罢免程序、诚实全靠系统提示词软约束。
3. **业界空白经 15+ 来源核实**:分级审批链、运行时边界伸缩、三层管辖组织、文件重要性分级、组织级 token 编制——全部无先例(详见业界报告 §C/§D);主流工程系统刻意把层级压在两层(Claude Code 明文"不做嵌套团队")。

## 1. 论点(要证明什么)

> 当任务被组织为持久容器、每个 agent 的权限被组织为可审批的动态边界、执行权被集中于独立测试群之后,**编码类任务的多 agent 组织可以在受控的 token 预算内交付质量合格的产出,且其治理行为(审批/罢免/谎报捕获)全程可审计、可回放、可测量**——从而正面回应 Anthropic"多数编码任务不适合 multi-agent"的判词(15× token、协调开销高)。

注意论点的诚实边界:不是"多 agent 更强",而是"**多 agent 在治理与成本受控后,第一次在编码域变得划算**"。

### 3.3 自建(三方全空白,= 项目的真实增量)

1. **动态边界对象**(#2):申请→审批→持久并入→收缩。superagent 明文拒绝动态扩张("wider scope means a new Ticket"),A2A 只有"任务中二次凭证"协议先例。**核心新概念,需要完整的新对象模型。**
2. **重要性地图**(#8):业界把文件当平等对象,零先例。
3. **三级管辖组织**(#7/10):主流刻意压在两层;ChatDev/MetaGPT 是流水线不是管辖层级。三级嵌套管辖是真实创新点。
4. **契约登记的组织内部版**(#17):A2A Agent Card 是跨组织协议;域内/跨域两档契约+专家团批准入册的组织内部制度是新的。
5. **治理闭环**(#13/15/18):证据链→罢免→人批;宪法层+执法器+治理程序,业界只有机制层没有治理层。
6. **审批式横向通信+组织级编制**(#21/22):业界横向通信全自由、数量全靠自觉;反主流设计,需用数据证明收益。

## 4. 概念模型(最小概念集)

沿 superagent 纪律:每个概念先回答"为什么不能是已有概念的属性"。本系统只有 **7 个域概念**:

```
Task(任务容器)      唯一的持久单元。挂:对话列表、事件账本、契约册、重要性地图、编制表。
                    = shepherd 总线 + superagent Ticket 的合体,但跨对话、带蒸馏记忆。
Mandate(授权)       可计算对象:版本、scope(文件夹模式列表)、强度、可代批范围。
                    审批=生成或扩张 Mandate;罢免=撤销;恢复前重验照抄 superagent。
Boundary(边界事件)  Mandate 的变更申请(扩张/收缩),走分级审批链。不是新实体,
                    是 Mandate 的 pending 变更 + 审批事件(回应"为什么不是新概念")。
Card(任务卡)        原子工作单元:goal/domain/files/contract/acceptance/budget/base_commit。
                    是 Task 的子记录,不是实体。
Contract(契约)      接口登记册的一条:签名+用途+错误语义+所属域+批准者。
                    域内契约二级批,跨域契约专家团批。
Report(报告)        agent 的状态 JSON(≤数十字段)+ 交付物引用。视察=读 Report。
Verdict(裁决)       测试群/专家团/审查 agent 的结构化结论:pass/fail+证据引用。
```

**数据面**:一切状态=事件账本的物化视图(照搬 shepherd ADR-001:SQLite 追加写、seq 全序、caused_by 因果、HMAC 审计链、重放重建)。大负载存 blob,事件只留引用与哈希。

**进程面**:core(零 I/O 纯逻辑)/adapters(I/O)/apps(组合根)三层依赖规则照搬 shepherd;没任务=没进程(常驻 Router 明确不做,事件到达由 OS 定时任务/手动触发冷启动)。

## 5. 拒绝的概念表(立项即冻结,防概念膨胀)

照 superagent 001-domain 的纪律,以下看似自然的实体**明确拒绝**:

| 拒绝 | 理由 |
|------|------|
| "人"作为域概念 | 人是 Trigger 的 actor 元数据+终审权持有者,不是可查询实体 |
| "部门/团队"实体 | 域只是文件夹分组+一个二级 agent 的管辖范围,不注册实体 |
| "聊天室/群聊" | 横向通信=申请-回复事件对,经审批;不存在自由消息面 |
| "全局实时仪表盘" | 状态=账本物化视图,按需拉取;无常驻面板进程 |
| "agent 随身记忆" | 记忆只存 Task;agent 上岗领状态、下岗写回,无私有记忆 |
| "绩效/晋升体系" | 信用只调耐心与预算(shepherd 红线:信用永远不买绕过边界) |
| "自动合并器" | 合并=专家团评审闸门+机械契约核对;不存在无人看管的自动合并 |
| "工具市场/插件机制" | 工具链=静态白名单,写入 agent 定义;不提供运行时扩展 |
| "专家团常驻会话" | 专家团里程碑触发+限频(皮层唤醒模式),讨论完即散 |
| "每 Thread 一个任务卡" | 一域可多卡并行,靠 files 不相交+base_commit 防冲突 |

## 6. 架构决策要点(立项即定,后补 ADR 细化)

1. **底座形态**:新建独立仓库(零第三方运行时依赖、Node strip-types 直跑,沿 shepherd);不做 DSH 插件依赖,v1 以本地 CLI+文件界面交付。
2. **授权是代码强制,不是 prompt 承诺**(superagent 教训):Mandate 校验、工具白名单、边界裁剪全在 host 代码;外部文本永远是数据。
3. **判定两层分离**:确定性 gate(资格)→模型评估(该不该);observe 模式作为一切新审批规则的默认态。
4. **诚实执法器**:信用×诱饵整套移植;加减分表按新组织重定义;"隐瞒"定义为可检测事实并入罢免证据链。
5. **执行边界**:v1 评估沿用 HooH 协议形态(裁决/快照/回滚四态)做轻量自建版;HooH 原服务是否直接接入=开放问题 O-2。
6. **成本纪律**:逐层字数预算(学 superagent 30/100/600/1500)、KV-cache 前缀稳定(Manus)、分电表+熔断(shepherd)、模型分档(shepherd 006 §1 直接可用)。
7. **规模预算**:core ≤3500 行(沿 shepherd 防蔓延表);新增机制先补 ADR。

## 7. 正面回应反方证据(立项答辩位)

Anthropic 判词:多数编码任务不适合 multi-agent(并行度低、协调开销高、15× token)。回应分四条,每条对应一个设计决策:

| 反方痛点 | 本设计的回应 |
|---------|-------------|
| 并行度低 → 协调吃掉收益 | 域切分+文件不相交派发(#4/22);契约先行消灭"拼不上"(#17)——协调成本从"人肉合并"降为"查表对接" |
| 15× token | 逐层预算+蒸馏账本+按需生灭(#12/16);写手低档小上下文(#10);业界实测中 token 用量解释 80% 性能方差,故预算线是产品约束不是建议 |
| 编码任务需要共享上下文 | 不共享。文件系统即上下文(Anthropic 附录同款):产物落盘、MD 通知、契约册——共享的是物,不是对话 |
| 简单任务开 50 个子代理 | 编制制(#22)+scaling 规则写进主 agent 提示词(Anthropic 教训直接采纳):单卡任务不开组织 |

## 9. 路线图(R1→R5,一期一器官,每期有验收)

**R1 核心循环(最高风险先行)**:Task+Card+写手(读写白名单)+测试群+三路合并+失败阶梯。账本用 shepherd 总线件。验收:一个 2 域小项目端到端跑通 ≥10 张卡,真模型(非 mock);产出每卡 token 成本、返工率、冲突率三张表。

**R2 契约与整合**:契约册+契约提案流+跨域审批+MD 通知+base_commit 合并实战。验收:两域写手互不见实现、仅凭契约完成一次真对接;契约背离被机械核对抓出 ≥1 次。

**R3 治理链**:Mandate 化+边界申请/收缩+分级审批+罢免流+observe 灰度。验收:全部审批事件可回放;一次真实罢免(注入一个谎报 agent)走完证据→申请→人批全链。

**R4 记忆与成本**:蒸馏账本+按需激活(冷启动→干活→零进程可演示)+分电表+编制限额。验收:没任务时 `ps` 零相关进程;跨对话续作一次(账本重放重建上下文)成功。
